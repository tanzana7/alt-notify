# UXレビュー

身内β公開前に、実装済みのSlash Commandを利用者目線で確認した記録です。

## 確認した導線

- `/main set`：このアカウントがメインであることと、次に `/link issue` を実行することを表示。
- `/link issue`：サブアカウントへ切り替え、`/link approve`、コード入力、承認ボタンの順を表示。
- `/link approve`：承認後にBot導入済みかつサブアカウント参加中のサーバーを自動監視すること、個別停止は `/watch off` であることを表示。
- `/watch off` / `/watch on`：現在のサーバーだけを変更し、OFFは再起動後も維持。
- `/watch status`：自動、ON、OFF、未連携を区別。
- `/status`：メイン・サブの役割、連携数と上限、表示名、個別OFF数を表示。内部IDは表示しない。
- `/unlink`：連携解除と未送信の対象通知停止を表示。全データ削除は `/account delete` に分離。
- `/account delete`：本人のボタン操作を要求し、連携・監視設定・未送信通知を削除。
- `/help`：最短設定、通知対象外、主要コマンドを短く表示。

## 既存仕様との整合

通知本文は扱わず、Bot自身の投稿、DM、サーバー非所属、チャンネル閲覧不可、明示的OFFは転送しません。Freeの連携上限は `FREE_LINK_LIMIT=5` を維持します。
