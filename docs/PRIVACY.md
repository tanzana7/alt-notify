# Alt Notify プライバシー情報（β版）

最終更新：2026-10-04

## DBへ保存する情報

- メインアカウントのDiscordユーザーID、表示名、登録日時
- 連携したサブアカウントのDiscordユーザーID、表示名、メインとの対応、登録日時
- プラン情報と更新日時（課金処理は未実装）
- 連携コードのハッシュ、発行・有効期限・使用日時。平文コードは保存しません
- サーバーごとの監視状態、Guild ID、作成日時
- 通知キューの状態、メインID、Message ID、Guild ID、Channel ID、対象アカウントID・表示名、対象ロールID、試行回数、時刻、失敗理由
- 重複排除用のメインID、メッセージID、作成日時

Guild名とChannel名は通知表示のためDiscordのキャッシュから参照しますが、DBには保存しません。メンバー情報も通知判定のためメモリ上のキャッシュで扱います。内部IDはユーザー向け通知DMには表示しません。

メッセージ本文、添付ファイル、DM本文、キーワード、全メンバー一覧は保存・転送しません。
非公開スレッドの投稿は通知対象外です。

## 利用目的

本人承認済みの連携を管理し、対象イベントの通知、重複排除、送信再試行、障害調査、バックアップと復元確認に利用します。運営統計は件数と状態のみを扱い、メッセージ本文は含みません。

## 保存場所と委託先

本番データは運営者が管理するOracle Cloud VM上のSQLiteに保存し、世代バックアップを同一VM内に保持します。VM障害への備えとして、運営者管理のWindows PCにもVM外バックアップを保存します。転送時にSHA-256とSQLite整合性を確認し、Windows側は現在最大14世代を保持します。Windows PCの停止中・未ログオン中は取得と世代更新が行われません。このバックアップによってDiscordのメッセージ本文やBot Tokenなどを追加保存することはありません。Discord公式APIを利用します。Healthchecks外部監視はURLを設定した場合だけ、Gateway・キュー・失敗状態を示すheartbeat/failリクエストを送信し、Discordデータは送信しません。現在の本番設定は運営者が管理します。

## 削除

サブ側の `/unlink` は連携を解除し、そのサブアカウントへの今後の通知を停止します。未送信・処理中の通知から対象を除き、他の対象がいなければ取消します。送信済みなど過去の通知履歴は保持される場合があります。メイン側の `/unlink` は指定したサブアカウントを同様に解除します。`/account delete` は連携の有無にかかわらず、実行した本人の保存済みデータを削除します。過去にメイン・サブを兼任していた場合も両方を削除します。unlink後でも、送信済み・失敗・取消済みを含む通知履歴から本人のIDと表示名を除去できます。バックアップコピーは保存世代の期限まで残る場合があります。

## ログ、バックアップと保持

ログには時刻、レベル、処理ID、アカウント内部ID、状態、エラー概要を記録する場合がありますが、Bot Token、連携コード、メッセージ本文は記録しません。通知キューと重複排除情報は運用上必要な期間、期限切れコードは定期 cleanup、バックアップとログは運用設定の保持期間で削除します。削除済みデータも、Oracle VM内・Windows側のバックアップ保持世代が失効するまで残る可能性があります。

一般的な問い合わせは [GitHub Issues](https://github.com/tanzana7/alt-notify/issues) を利用できます。公開Issueに個人情報・認証情報を投稿しないでください。個人情報に関する相談では、まず非公開の連絡方法を運営者へ確認してください。
